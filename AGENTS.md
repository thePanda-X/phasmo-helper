# Repository Instructions

## Toolchain And Commands

- Use Go 1.25.x (`go.mod` declares 1.25.0), Wails CLI v2.13.x, and Node `^20.19.0 || >=22.12.0` (the locked Vite 7.3.6 engine requirement).
- For a clean checkout, run these from the repository root in order:

```text
npm ci --prefix frontend
npm run build --prefix frontend
go test ./...
```

- `frontend/dist` is ignored but is embedded by `main.go`; without the frontend build, full-root Go builds and `go test ./...` fail at the `go:embed` directive. `go test ./internal/...` does not need `frontend/dist`.
- Use `wails dev` for the integrated desktop/Vite development loop. `wails.json` configures `npm install`, `npm run dev`, and `npm run build`; do not start a separate frontend server unless isolating frontend work.
- Use `wails build` for a production package; the Windows executable is written under `build/bin/`.
- Run one root test with `go test . -run '^TestNormalizeKeybindCanonicalizesModifiersAndKeys$'`; run one internal test with `go test ./internal/bpm -run '^TestTrackerIgnoresKeyboardRepeat$'`.
- There are no frontend test, lint, formatter, or typecheck scripts. `npm run build --prefix frontend` is the configured frontend verification step.

## Architecture Boundaries

- `main.go` configures the native Wails window and embeds `frontend/dist`; `app.go` is the Go-to-JavaScript API/event boundary. Domain code lives in `internal/bpm` and `internal/ghosts`.
- `frontend/src/App.jsx` owns frontend state and Wails integration; React components under `frontend/src/components` render the dashboard, settings, and overlay. `frontend/src/style.css` owns styling.
- `frontend/wailsjs/**` is generated by Wails. Never edit it manually; run `wails dev` or `wails build` after changing exported `App` methods or bound Go models.
- Global input, overlay behavior, foreground detection, and tray integration use `*_windows.go` implementations with `*_other.go` stubs. Windows-tagged tests do not run on other operating systems.
- Keybinds and overlay layout persist through `os.UserConfigDir()/PhasmoHelper` (`settings.json` and `overlay-layout.json`). Tests that save settings must isolate both `APPDATA` and `XDG_CONFIG_HOME` as `settings_test.go` does.

## Cross-Layer Gotchas

- Overlay module IDs are a closed set shared by `overlay_layout.go`, the `SetModuleLayout` allowlist in `app.go`, and layout state/components under `frontend/src`; update all three when adding or renaming a module.
- Hotkey-driven changes cross the native polling code, `App.handleKeybind` Wails events, and frontend `EventsOn` handlers. Preserve those event names and payload shapes across both sides.
- Tracker measurement is Go state, but discarded ghosts, selected evidence, and hunt timer history are frontend session state. Full-session reset therefore crosses the `run.reset` event rather than only calling `Tracker.Reset`.
- `internal/ghosts/data/ghosts.json` is embedded. Evidence is not stored there: `Load` injects it from `standardEvidence` in `internal/ghosts/catalog.go`. Roster updates must keep the JSON entries, evidence map, catalog version, and the fixed count assertion in `catalog_test.go` consistent.
- `frontend/dist` and `build/bin` are generated artifacts. Edit `frontend/src` or packaging sources under `build/windows`, not generated output.
